# System Requirements Specification: v1.4 Modern Repository Architecture & Directory Simplification

> **Milestone:** v1.4 — Repository Architecture Modernization & Directory Simplification  
> **Target:** Hindi Reel Studio Codebase  
> **Status:** Draft / Specification Phase  

---

## 1. Executive Summary

Over successive feature releases (v1.0 through v1.3), Hindi Reel Studio has grown from a prototype script into a production dual-engine pipeline and standalone native macOS desktop application. However, as capabilities grew, the repository root accumulated loose shell scripts, exploratory documents, backup files, and image assets.

The goal of **v1.4** is to modernize and simplify the project directory structure according to modern Python and macOS software engineering best practices without breaking any runtime behavior, test suites, or the PyInstaller packaging workflow.

---

## 2. Problem Statement (Current State Analysis)

1. **Root Directory Clutter**:
   - The repository root currently contains more than 25 mixed files and directories.
   - Multiple root shell scripts exist for launching or managing background services (`run.sh`, `HindiReelStudio.command`, `setup_background_service.sh`, `stop_background_service.sh`).
   - Stale backup and temporary log files persist in root (`app.py.bak_preview_fix`, `streamlit.log`).
2. **Scattered Documentation**:
   - Multiple large specification documents (`AGENT_ARCHITECTURE.md`, `REQUIREMENTS.md`, `NEXT_FEATURES.md`, `TODO.md`, `RELEASE_NOTES.md`, and the `v3/` exploration folder) live directly at top-level instead of a standardized `docs/` hierarchy.
3. **Scattered Assets**:
   - Image assets and icon directories (`camera_icon_512.png`, `AppIcon.iconset/`) sit directly in the root directory rather than an `assets/` folder.
4. **Maintenance Overhead**:
   - New contributors or automated packaging scripts must navigate loose files rather than a predictable, standardized layout.

## 4. Functional Requirements

### FR-1: Clean Root Directory
- The root directory must contain strictly:
  - Application entrypoint (`app.py`)
  - Dependency manifests (`requirements.txt`, `pyproject.toml` if applicable)
  - Core project governance (`README.md`, `CONTRIBUTING.md`, `AGENTS.md`, `GEMINI.md`, `.gitignore`)
  - Standard top-level module folders (`core/`, `agents/`, `tools/`, `prompts/`, `macos/`, `scripts/`, `assets/`, `docs/`, `tests/`)
- Stale backup files (`app.py.bak_preview_fix`) and runtime logs (`streamlit.log`) must be removed from git tracking and ignored.

### FR-2: Centralized Documentation Hierarchy (`docs/`)
- Relocate all architectural and specification documents into `docs/`:
  - `AGENT_ARCHITECTURE.md` ➔ `docs/ARCHITECTURE.md`
  - `REQUIREMENTS.md` ➔ `docs/REQUIREMENTS.md`
  - `RELEASE_NOTES.md` ➔ `docs/RELEASES.md`
  - `NEXT_FEATURES.md` + `TODO.md` ➔ `docs/ROADMAP.md`
  - `v3/` folder ➔ `docs/v3_spec/`
- Ensure all relative document links inside markdown files are updated to resolve cleanly.

### FR-3: Centralized Assets Directory (`assets/`)
- Move static media and icons into `assets/`:
  - `AppIcon.iconset/` ➔ `assets/AppIcon.iconset/`
  - `camera_icon_512.png` ➔ `assets/images/camera_icon_512.png`
- Update [`scripts/build_macos_app.sh`](file:///Users/abhiraj/Documents/news/agent/scripts/build_macos_app.sh) and [`scripts/generate_dev_icon.py`](file:///Users/abhiraj/Documents/news/agent/scripts/generate_dev_icon.py) to reference the new assets location seamlessly.

### FR-4: Consolidated Scripts & Launchers (`scripts/`)
- Relocate and consolidate loose launchers from root into `scripts/`:
  - Move `run.sh` to `scripts/run.sh` (with a lightweight root proxy or symlink if needed).
  - Consolidate `setup_background_service.sh` and `stop_background_service.sh` into `scripts/service.sh` (`service.sh start|stop|status`).
  - Move macOS double-clickable launcher `HindiReelStudio.command` to `scripts/` or retain lightweight proxy.

   - Internal document links between `README.md`, `docs/`, and agent rule files must be verified.
